# Хеш-функции Этапа 8

## 8.2 FNV-1a (хорошая хеш-функция)

Реализация в `src/fnv_hash.h`:
- Использует 64-битный алгоритм FNV-1a (Fowler-Noll-Vo).
- Offset basis: `14695981039346656037`
- Prime: `1099511628211`
- Обеспечивает отличное распределение даже для похожих строк (анаграмм).

## 8.3 bad_hash (плохая хеш-функция для контраста)

Реализация в `src/bad_hash.h`:
- Простая сумма ASCII-кодов символов.
- Дает колоссальное количество коллизий для строк с одинаковым набором символов.

### Демонстрация коллизий

| Строка | bad_hash | fnv1a_hash |
|--------|----------|------------|
| "abc"  | 294      | 16654208175385433931 |
| "bca"  | 294      | 17784708276267337    |
| "cab"  | 294      | 17717993371968242833 |

**Вывод:** `bad_hash` дает одинаковый хеш для всех анаграмм. В хеш-таблице они все попадут в одну корзину, и поиск деградирует до O(N). `fnv1a_hash` дает уникальные значения, гарантируя O(1).

### Бенчмарк вычисления (100,000 ключей, сборка -O3)

| Функция  | Время (ms) | Сложность вычисления |
|----------|------------|----------------------|
| FNV-1a   | 0.424      | XOR + умножение      |
| bad_hash | 0.288      | Только сложение      |

**Парадокс:** `bad_hash` вычисляется быстрее, потому что использует только операцию сложения. Однако в контексте хеш-таблицы это не имеет значения: выигрыш в наносекундах на вычисление хеша полностью перечеркивается деградацией поиска с O(1) до O(N) из-за коллизий.

### Вывод
Качество хеш-функции критично для производительности хеш-таблицы. Плохая функция приводит к длинным цепочкам в корзинах и потере преимуществ хеширования. FNV-1a обеспечивает предсказуемую производительность и равномерное распределение.
